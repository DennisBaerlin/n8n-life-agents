# Paperless-Paket — Domänen-Regeln (lädt beim Arbeiten in `packages/paperless/`)

Schlanker **Lese-Zugang** auf die Paperless-NGX-v3-Instanz des Owners (Suche, Dokument, Dokumenten-Chat); Ingest/Metadaten macht paperless-gpt außerhalb. Das Paket verarbeitet keine Dokumente, hält keine eigenen Daten (Schema `paperless` ist leer) und **schreibt nie** nach Paperless. Paket-Gesetze → `packages/CLAUDE.md`; Werkzeug-Vertrag → `docs/package-contract.md` §5.1.

- Die drei Werkzeuge `tool_search_documents`, `tool_get_document`, `tool_ask_documents` (Alias `paperless:<name>`; Calls → `docs/reference/packages.md` *Write-Tools-Katalog*) sind Paket-Tool-Services: Manifest-`inputs` sind die **eine** Quelle für `$fromAI`-Schema und Prüfung (`paperless_common.ps1 New-PaperlessParseArgs`); Aufruf nur über `agent.sub_dispatch_tool` → `core.fn_resolve_service` (`permission: adults_only`, Kinder nie) — auch der eigene Assistent (`Add-ServiceTools -Own`); literal bindet nur der Test-Harness.
- Adresse `general.paperless_url` zur Laufzeit lesen (`core.fn_config_get` unter `paperless_ro`). Das Token ist bewusst `required: false`: ein Update ohne Token bricht nicht ab, die Werkzeuge melden `not_configured`. Fehler als feste Codes (`paperless_auth_failed`, `not_found`, `paperless_api_version_unsupported`, `paperless_ai_disabled`, `paperless_unreachable`), Retry nur bei Netzfehlern.
- Jede Erfolgs-Antwort trägt `untrusted` als erstes Feld; die Regel steht einmal in `packages/core/contexts/global_instructions.md` *Untrusted content*.
- `agent.paperless_assistant` ist ein Klon des estate-Advisors (Modell `model.paperless_assistant`, Anthropic = bezahlt/nicht-trainierend); Instruktionen `contexts/paperless_assistant_instructions.md` (erst suchen; Nummer → lesen; ausdrückliche KI-Frage → fragen).
- Tests: `tests/db/paperless/*`, Mock `tests/mock_paperless/server.js` + `scripts/dev/enable_mock_paperless.ps1` → `infra_test.ps1`; LLM `tests/agent/paperless/paperless_cases.json`. Das Test-DB-Image bleibt `pgvector/pgvector:pg17`, sonst bricht `test_paperless_retire.sql` (`paperless:V001` baut die alte Pipeline zurück). Kein `backup`-Block (keine Daten).
