# Scripts — Konventionen (lädt beim Arbeiten in `scripts/`)

Policy (Scripts-Only, PowerShell-Tool, Owner-Fenster, eigene Container) → Root-`CLAUDE.md` *Scripts*; PowerShell-Encoding/`-Verbose`/Dot-Sourcing → `.claude/rules/powershell.md` (lädt beim Öffnen einer `.ps1`). Pro Skript gilt sein Kopf-Kommentar (keine Skript-Referenz in Doku); Gate-Matrix → `CONTRIBUTING.md` *The enforcement gates*, Hooks → `.pre-commit-config.yaml`. Substrat-, Mock-LLM-, Deploy- und `.env`-Mechanik → `docs/reference/scripts.md` (on-demand).

## Skripte aus Claude Code ausführen

- **Der Owner-Fenster-Hook matcht die Dateinamen der gesperrten Suiten überall im Befehlstext** (auch grep/cat) → Suite-Dateien nur mit Read/Grep öffnen. Claude ruft `grant_owner_window.ps1` nie selbst auf und schreibt `owner_grant.txt` nie (der Hook verweigert beides).
- **Ein offenes Owner-Fenster gilt für alle Sessions und Worktrees zugleich:** `grant_owner_window.ps1` schreibt immer in den Haupt-Checkout und nur diese Datei zählt, solange es offen ist, darf also jede laufende Session bezahlte Suiten starten. Owner- und App-Hook teilen sich Suche und Schreib-Erkennung (`.claude/hooks/lib/grant_window.ps1`): Scheitert `git` oder fehlt das Repo, bleibt das Fenster zu. Test: `scripts/dev/owner_window_hook_test.ps1`.
- **App-Fenster (Hook `.claude/hooks/enforce_app_window.ps1`):** Die Mini-App (`build/app`, `core.main_app_serve`, `fn_app_*`, Texte `<pkg>.app.*`, `app_screens`) ändert Claude nur im Fenster, das der Owner öffnet (`grant_app_window.ps1`, Default 60 Min), getrennt vom Owner-Fenster der Suiten. Test: `scripts/dev/app_window_hook_test.ps1`.
- **Datei-Writes in PowerShell nur mit absolutem Pfad** (am besten Write-/Edit-Werkzeug): Ein `Set-Location <worktree>` im selben Befehl hielt nicht, der relative Write landete still im Haupt-Checkout. Danach `git -C <worktree> status` prüfen.
- `db_apply.ps1 -File` mit mehreren Zielen: unquoted komma-getrennt (`-File a.sql,b.sql`) oder ein gequotetes Glob (`'packages\finance\db\migrations\R__fn_*.sql'`); ein gequoteter `'a.sql,b.sql'`-String wird als ein Glob gelesen und schlägt fehl.
- **Vorschauen in der Desktop-App** (`.claude/launch.json`, Browser-Pane): `mini-app` = Mini-App ohne Substrat mit erfundenen Werten (`scripts/dev/serve_app_preview.ps1`, hell/dunkel per `?scheme=`), `ui-compare` = zuletzt gebauter Vorher/Nachher-Vergleich der Mini-App (`build_ui_compare.ps1`), `docs-site` = Hugo-Site live, `desktop-app` = Start-App mit Befehls-Attrappe (`scripts/dev/serve_desktop_preview.ps1`, Fälle per `?state=`), `wizard` = Einrichtungs-Wizard mit festgehaltenen Seiten-Modellen (`scripts/dev/serve_wizard_preview.ps1`), `explain-art` = Erklär-Bilder in allen Sprachen und hell/dunkel (`scripts/dev/serve_art_preview.ps1`), `n8n-test` = Oberfläche des Standard-Substrats (eigener Port → Adresse im Pane anpassen). Die Vorschau zeigt nur an; Änderungen an der App bleiben Sache des App-Fensters.
- **CI-Ampel:** `check_ci_status.ps1` zeigt den letzten GitHub-Lauf je Workflow auf `main`; der SessionStart-Hook meldet Rot an jede Session (dann zuerst fixen, dem Owner melden). Lokal laufen die Node-Checks des `workflow_lint` per Docker, nie mehr übersprungen — ein Lint-Unterschied zwischen lokal und CI ist ein Bug.
- **Freie Gates auf GitHub** (`.github/workflows/free-gates.yml`, Ablauf → `CONTRIBUTING.md`): nur lokal geprüft sind PowerShell 5.1, echter Test-Bot, echte API (`llm_gateway_test` Fall h) und bezahlte Suiten. Die Suiten laufen deshalb unter beiden PowerShell-Versionen: Pfade an native Tools nicht als `"$RepoRoot\..."`, sondern über `Join-Path`/`Resolve-Path`.

## Deploy-Modell & Substrat

- **Keine Instanz ist Sync-Ziel:** Workflows, Config/AI-Models und Instruktions-Contexts kommen nur aus dem getrackten Baum (`build.ps1` → `bootstrap_test_n8n.ps1 -Reset` → `provision.sh`; Prod `lifeagents update`). Neue Workflows bekommen eine selbstvergebene id im Dateinamen, kein POST-zum-Minten. PII-Contexts entstehen nur per Onboarding, nie per Seed.
- `N8N_URL`/`N8N_API_KEY` der Tiers kommen ausschließlich aus `.local/n8ntest_state.<container>.json` (`Get-TestN8nStateFile`/`Get-TestN8nConnection`; je Container eine Datei, ein zweites Substrat überschreibt nichts), nie aus `.env` → kein versehentlicher Prod-Zugriff. Container-DB nur über `Invoke-TestN8nPsql` (Peer-Auth, `apply_schema.sh`-Pfad), nie `db_apply.ps1` (zielt auf die db_test-DB).
- **Schnellpfad vs. kalt:** `-Reset` startet aus dem lokalen Basis-Image (Software vorinstalliert, Neubau automatisch bei Pin-/Baustein-Änderung; Mechanik im Skript-Kopf). Ändert ein Branch den Install-Kern (der Schnellpfad meldet es, Dateiliste in `Show-InstallCoreHint`) → vor dem Push `-Reset -Cold`; Release-Check `-Version` ist immer kalt.
- **Container nur mit `docker rm -fv` abbauen** (`-Down`, `-Reset`, SessionEnd-Hook): Die Images deklarieren `VOLUME`, Docker legt dafür ein namenloses Volume an, das `rm -f` verwaist zurücklässt. Benannte Volumes bleiben. Test: `scripts/dev/docker_volume_cleanup_test.ps1` (prüft auch statisch, dass kein `docker rm` ohne `-v` dazukommt).
- **Docker aufräumen:** `scripts/dev/docker_cleanup.ps1` listet eigene Altlasten (gestoppte Test-Container samt ihren anonymen Volumes, eigene dangling Images; verwaiste anonyme Volumes nur mit `-IncludeOrphanAnonymousVolumes`, die treffen auch Fremdes), `-Apply` löscht; nie `prune`/`--all`, Fremdes bleibt. DB-Test-Ports (`DBTEST_PG_PORT`) vergibt dieselbe Reservierung wie die Substrate (`reserve_substrate_slot.ps1 -FreeDbPort`; `bootstrap_test_db.ps1` prüft und trägt ein).
- **Nach Merge/Pull** bauen die Hooks post-merge und post-commit (`post_merge_regenerate.ps1`, braucht `prek install --hook-type post-merge --hook-type post-commit`) UI-Tokens und Site neu, wenn deren Quellen im Merge geändert wurden; das Ergebnis bleibt unkommittet im Arbeitsbaum, und scheitert ein Generator (z. B. fehlt Hugo), steht die Warnung mit dem Nachhol-Befehl in der Ausgabe. Git ruft post-merge nur bei sauber durchgelaufenem Merge, nach einem von Hand aufgelösten Konflikt-Commit läuft stattdessen post-commit (nur bei Merge-Commits aktiv). Fehlt ein Hook im Clone (vor seiner Einführung verdrahtet), meldet `setup_dev_env.ps1 -Verify` es; Abhilfe `install_git_hooks.ps1`. Test: `scripts/dev/post_merge_regenerate_test.ps1`.
- `.env`-Keys des Substrats: Layout = `.env.example` (`doc_lint` 7b erzwingt es); `TEST_HARNESS_SECRET` ist Pflicht, `TEST_TELEGRAM_BOT_TOKEN` ist nie der Prod-Bot.
- **Laufende Executions nie per Roh-SQL zählen:** Läufe mit `saveDataSuccessExecution: none` (z. B. `core.sub_show_thinking`) löscht n8n am Ende nur weich (`deletedAt`, Pruning-Puffer 1 h) und lässt `status = 'running'` stehen, bis der Hard-Delete-Durchlauf sie entfernt; Pausen unter 65 s schlafen im Prozess (kein `waitTill`). Live-Diagnose daher über die API (`executions?status=running`) oder SQL mit `"deletedAt" IS NULL`.

## Mock-LLM (gratis Tier, Claude darf ihn fahren)

- `enable_mock_llm.ps1` biegt den Upstream des LLM-Gateways per systemd-Laufzeit-Drop-in auf `tests/mock_llm/server.js`; das Drop-in überlebt keinen Container-Neustart → jede Suite prüft den tatsächlichen Upstream (`Assert-LlmGatewayUpstream -Expect mock|real`). Prod-Workflows bleiben unangetastet.
- Szenarien (`tests/mock_llm/scenarios.json`) müssen **alle Pflicht-`$fromAI`-Felder** als Args tragen (sonst registriert der Call nicht); Tool-Namen per `mock_route_test.ps1 -Discover` ablesen (Orchestrator-Routen sind sanitisiert, `Call_agent_finance_`). `mock_lint.ps1` hält Szenarien ↔ Cases commit-time konsistent.
- Ablauf: `bootstrap_test_n8n.ps1` → `enable_mock_llm.ps1` → `enable_mock_telegram.ps1` → `mock_route_test.ps1` → `-Down`. Alle freien Gates auf einmal (Merge-/Release-Stand): `scripts/dev/run_free_gates.ps1` (schaltet alle Mocks selbst ein, Reihenfolge + Zusammenfassung im Skript-Kopf); `-Parallel` verteilt die Suiten auf zwei Substrate (`<container>-b`, Port +1, nach dem Lauf abgebaut). Crons startet `Start-TestCron` (`test_n8n_state.ps1`) sofort über `core.cron_run.test_harness` (Einstieg `Test run`, Build-Workflow).
